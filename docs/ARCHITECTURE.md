# Satalitte Physics v2 — Architecture & Module Contract

Static site for **GitHub Pages**: plain ES modules, no bundler, no runtime CDN.
All URLs are **relative** (`./src/...`, `./vendor/...`, `./assets/...`) so the
site works under `https://<user>.github.io/Satalitte-Physics/`.

```
index.html              entry, import map, DOM skeleton, loading screen
styles/main.css         all styling (HUD, panels, labels, toasts, modal)
src/main.js             bootstrap + game loop + glue (owner: lead)
src/camera.js           focus/follow/chase camera on top of OrbitControls (lead)
src/input.js            picking, keyboard, drag-to-launch (lead)
src/physics/*.js        simulation, pure JS, no three.js import (lead)
src/render/*.js         scene, shaders, visuals (owner: Technical Artist)
src/ui/*.js             HUD / panels / modal / settings (owner: Frontend Developer)
vendor/                 three r185 + addons, lil-gui 0.21 (generated by `npm run vendor`)
assets/textures/        textures (see list below)
legacy/                 the original 2021 version, kept playable
tests/                  node:test unit tests for physics
```

Import map (in `index.html`):
```json
{ "imports": {
  "three": "./vendor/three/build/three.module.min.js",
  "three/addons/": "./vendor/three/addons/",
  "lil-gui": "./vendor/lil-gui/lil-gui.esm.min.js"
} }
```
Available addons: `controls/OrbitControls.js`, `renderers/CSS2DRenderer.js`,
`postprocessing/{EffectComposer,RenderPass,UnrealBloomPass,OutputPass,ShaderPass}.js`,
`objects/Lensflare.js`. Do not import other addons (they are not vendored).

## Frames & units

* **Physics** works in **km, s**, Float64, arrays `[x, y, z]`.
* World frame is **equatorial, Y-up**: +Y = Earth's north pole, the XZ plane is
  the equator, +X = vernal equinox. Eastward rotation is a positive rotation
  about +Y (three.js `rotation.y` increases ⇒ +X turns toward −Z).
* **Rendering** is **Earth-centred** and **1 scene unit = 1000 km**:
  `renderPos = (body.pos − earth.pos) / 1000`. Earth sits at the origin.
  Earth radius = 6.371 units, Moon radius = 1.7374, Moon distance ≈ 384.
* three's `SphereGeometry` + equirectangular map puts longitude 0 at local +X
  and 90°E at local −Z, so **`earthGroup.rotation.y = earthRotationAngle`**
  (Greenwich sidereal angle, radians) aligns the textures with real geography.
* The renderer uses `logarithmicDepthBuffer: true` (scene spans 0.0001–20000
  units). **Every custom `ShaderMaterial` must include the logdepth chunks**:
  `#include <common>` + `#include <logdepthbuf_pars_vertex>` / `<logdepthbuf_vertex>`
  in the vertex shader and `<logdepthbuf_pars_fragment>` / `<logdepthbuf_fragment>`
  in the fragment shader.

## Render module contract (Technical Artist) — `src/render/`

All factories take plain data and return objects; no global state, no DOM
outside the canvas/label layer. Each file default-free, named exports only.

### `src/render/renderer.js`
```js
export function createRenderer(container, { quality }) → {
  renderer, scene, camera,          // camera: PerspectiveCamera fov 45, near 1e-4, far 2e5
  labelRenderer,                    // CSS2DRenderer, its domElement appended to container
  setSize(w, h),                    // call on resize (handles pixel ratio cap per quality)
  setBloom(enabled),
  setQuality('low'|'medium'|'high'),// pixel ratio + bloom resolution
  render(),                         // composer (or plain) render + label render
}
```
`quality`: high → pixelRatio ≤ 2, bloom on; medium → ≤ 1.5; low → 1, bloom off by default.
Tone mapping ACES Filmic, output sRGB. Bloom must be subtle (threshold high) so
only the sun, atmosphere rim, re-entry plasma and impact flashes glow.

### `src/render/textures.js`
```js
export function loadTextures(renderer, { quality, onProgress }) → Promise<Textures>
// onProgress(fraction 0..1, label). Uses THREE.LoadingManager.
// Correct colorSpace (SRGB for albedo/lights/stars, NoColorSpace for data maps),
// anisotropy = renderer.capabilities.getMaxAnisotropy() (≤ 8), mipmaps on.
// quality 'low' loads earth_day_2048, otherwise earth_day_4096.
// Must resolve even if a texture fails (use a 1×1 fallback and console.warn).
```

### `src/render/earth.js`
```js
export function createEarth(textures, { quality }) → {
  group,                 // THREE.Group at origin; add to scene
  surface,               // the pickable/occluding Mesh (radius 6.371)
  update({ rotation, sunDir, cameraPosition, time, settings }),
  // rotation: Earth sidereal angle (rad) → apply to the rotating part only
  // sunDir: THREE.Vector3 unit vector from Earth toward the Sun (world)
  // settings: { clouds:boolean, atmosphere:boolean, cityLights:boolean }
  addImpactMarker(localDirection /* unit Vector3 in Earth-fixed frame */, color),
  clearImpactMarkers(),
}
```
Requirements: custom day/night shader (soft terminator, city lights on the night
side, specular sun glint on oceans only, normal-mapped relief), separate cloud
shell (slow independent drift, lit by sun, casts no light on night side),
atmosphere shell with Fresnel rim + sunset-coloured terminator glow (additive,
back-side), all following `sunDir`. Impact markers are children of the
rotating group so they turn with the planet.

### `src/render/moon.js`
```js
export function createMoon(textures) → {
  group, surface,        // radius 1.7374
  update({ position /*Vector3 render units*/, sunDir, earthPosition }),
  // tidally locked: same face points toward earthPosition
  addImpactMarker(localDirection, color), clearImpactMarkers(),
}
```

### `src/render/sky.js`
```js
export function createSky(textures, scene) → { update({ sunDir, camera }) }

// follows the camera; must not z-fight or clip), DirectionalLight from sunDir,
// faint ambient, a visible sun disc + Lensflare placed far along sunDir.
```

### `src/render/satellite.js`
```js
export function createSatelliteVisual({ color, kind /* 'satellite'|'probe'|'debris' */ }) → {
  object,                // THREE.Object3D, add to scene
  update({ position, velocityDir, camera, heating /*0..1*/, selected, sunDir }),
  // Procedural low-poly spacecraft (bus + solar panels / antenna). Keeps a
  // minimum on-screen size (~10-14 px) by scaling with camera distance, but
  // shrinks to true-ish scale when the camera is very close. Oriented prograde.
  // heating>0 → orange/white plasma glow (re-entry). selected → highlight ring.
  setColor(hex), dispose(),
}
export function createImpactFlash(scene, position, color) → { update(dt) → boolean alive, dispose() }
```

### `src/render/trail.js`
```js
export class Trail {
  constructor({ color, capacity = 4000 })
  object                  // THREE.Line (or LineSegments) — add to scene
  push(x, y, z)           // render units; ring buffer, no per-frame allocations
  clear()
  setColor(hex); setVisible(bool); setMaxPoints(n)   // n ≤ capacity
  dispose()
}
// Fades from transparent (oldest) to opaque (newest). Additive, depthWrite false.
```

### `src/render/orbitLine.js`

## UI module contract (Frontend Developer) — `index.html`, `styles/main.css`, `src/ui/`

The UI knows nothing about three.js or physics internals; it renders plain
data and reports user intent through handlers.

### `index.html`
Contains the import map above, `<link rel="stylesheet" href="./styles/main.css">`,
a full-viewport `<div id="viewport">` (canvas host, owned by render), a
`<div id="ui">` overlay root, a loading screen `#loader`, a `<noscript>` and a
WebGL-unavailable message, `<script type="module" src="./src/main.js">`.
Proper `<meta>` (viewport, description, theme-color, Open Graph), a favicon
(inline SVG data URI is fine), `lang="en"`.

### `src/ui/hud.js`
```js
export function createHUD(root, handlers, { settings, presets, warpSteps }) → hud
```
`handlers` (all optional, UI must guard):
```
onTogglePause()                 onWarp(index)            // index into warpSteps
onSelect(id)                    onFocus(id)              onDelete(id)
onLaunchPreset(presetId)        onLaunchCustom({ altitudeKm, speedFactor, inclinationDeg, eccentricity? })
onManeuver(direction, dvMs)     // direction: 'prograde'|'retrograde'|'normal'|'antinormal'|'radialIn'|'radialOut'
onCameraMode(mode)              // 'orbit' | 'chase'
onSettingChange(path, value)    // e.g. ('graphics.bloom', false)
onReset()                       onClearDebris()          onResetView()
```
`presets`: `[{ id, name, description, group }]` (group: 'Earth orbit' | 'Special').
`warpSteps`: numbers (time multipliers), e.g. `[1, 10, 60, 600, 3600, 21600, 86400]`.
`settings`: nested object (shape below) — the UI may bind lil-gui to it, but
must report every change via `onSettingChange(path, value)`.

`hud` methods (called by main, must be cheap — main calls `setTime`/`setTelemetry`
at ~10 Hz, never rebuild DOM when nothing changed):
```
setLoading(fraction, label)     hideLoading()            showFatal(message)
setTime({ date /*Date*/, warpIndex, paused, warpLimited /*bool*/ })
setBodies([{ id, name, kind, color /*'#rrggbb'*/, status /*'orbiting'|'suborbital'|'escaping'|'impacted'*/ }])
setSelection(id | null)
setTelemetry(t | null)          // see below
setCameraMode(mode)
toast(message, type /* 'info'|'success'|'warn'|'danger' */)
setDeltaVUsed(ms)
```
Telemetry object (numbers in SI-ish display units; UI formats):
```
{ id, name, kind, color, centralBody: 'Earth'|'Moon',
  altitudeKm, speedKms, periapsisKm (altitude), apoapsisKm (altitude, Infinity if unbound),
  periodS (Infinity if unbound), eccentricity, inclinationDeg, semiMajorAxisKm,
  specificEnergy /*MJ/kg*/, latitudeDeg, longitudeDeg, status, dragAccel /*m/s²*/,
  heating /*0..1*/, distanceToMoonKm, ageS, deltaVUsedMs }
```
Layout: top bar (brand, UTC sim clock, ⏯, warp − / label / +, help), left
column (object list + selection telemetry + maneuver pad with Δv step buttons
1/10/100/1000 m/s and "hold to burn" hint), right column (Launch: preset cards
+ custom form; Settings: lil-gui mounted in a container, not floating), bottom
hint bar with shortcuts, toasts stack, help/about modal (controls, the physics
used, credits and the reference links from `Links for project.txt`). Panels
collapsible; on narrow screens (< 820 px) become slide-in drawers with toggle
buttons; touch-friendly (≥ 40 px targets). Keyboard focus visible, ARIA labels,
`prefers-reduced-motion` respected. Visual style: dark translucent "mission
control" glass panels, one accent colour, tabular numerals for telemetry.
**The UI must not swallow canvas pointer events outside panels**, and keyboard
shortcuts must not fire while typing in inputs (main checks
`event.target.closest('input, select, textarea, [contenteditable]')`).

## Physics module (lead) — `src/physics/`

`Simulation` (pure JS): Earth + Moon as mutually attracting bodies around the
barycentre, satellites as test particles feeling Earth (+ J2) and Moon,
exponential atmosphere drag in the co-rotating atmosphere, leapfrog (KDK)
integration with adaptive sub-stepping, impact / escape detection, orbital
elements, low-precision ephemerides so the simulation starts with the real
Sun direction, Earth rotation (GMST) and Moon position for "now".

## Contract update — ORBITAL-OS prototype features (supersedes the above where different)

The user's prototype (`legacy/orbital-os.html`) is the starting point; v2 keeps
all of its features and visual language.

**Physics** (`Simulation`): every spacecraft carries propellant (default 1.2 t
dry, 420 kg fuel, 18 kN, Isp 340 s). `setThrust(id, dirs)` = held thrusters
(finite burn at F/m in the local orbital frame, fuel flow F/(Isp·g0), warp capped
at ×10 while firing). `circularize(id)`, `hohmann(id, targetAltKm)` (the second
burn fires automatically at the opposite apsis), `refuel(id)`, `applyImpulse`
are paid for with the rocket equation. Events: `impact`, `escape`, `fuelOut`,
`burn`.

**UI** additions: thruster pad is hold-to-burn → `onThrustStart(dir)` /
`onThrustEnd(dir)`; `hud.setThrusting(dirs)`; autopilot `onAutopilot('circularize'
| 'hohmann' | 'refuel')`, `onTargetAltitude(km)`; camera modes `'orbit' | 'chase'
| 'nadir'` + ECI button → `onResetView()`; `hud.pushHistory({ simTime, altKm,
speedKms, lat, lon })`, `hud.clearHistory()`, `hud.setAlert(text|null, level)`;
navball, ground track and altitude/speed chart instruments. Settings: `physics.throttle`
(5–100 %) replaces `thrustRate`; new `graphics.markers`, `graphics.targetRing`.
Telemetry adds `raanDeg, argpDeg, trueAnomalyDeg, flightPathAngleDeg,
densityKgM3, j2Accel, gravityAccel, escapeVelocityKms, fuelKg, maxFuelKg,
dvRemainingMs, thrustN, metS, autopilot`.

**Render** additions: satellite plume (`thrustDir` in `update`), dashed
`OrbitLine` option + `setNodes(an, dn)`, `src/render/grid.js` equatorial grid.
